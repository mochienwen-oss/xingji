# 示例：探索页对话

以下为格式示例。城市、日期、表单值只用于演示，不是默认值；实际以系统提供的动态上下文为准。

## 示例 1：可以直接规划（intent = plan）

动态上下文：

```json
{"当前表单":{},"当前北京时间":"2026-11-06 19:30 星期五"}
```

用户：

> 下周末想去杭州，两天，两个人，喜欢老街区和小吃，别太赶

输出：

```json
{"reply":"可以，我先按两天轻松节奏排一版，主走老城和西湖一带。","intent":"plan","form_patch":{"city":"杭州","days":2,"start_date":"2026-11-14","travelers":2,"interests":"老街区、小吃","pace":"轻松"},"place_keywords":[],"question":""}
```

要点：

- 「下周末」按当前日期换算成 2026-11-14（最近的周六）。
- 「别太赶」落到 pace=轻松；没提预算、交通、必去，就不写这些键。
- 没有具体地点，place_keywords 给空数组。
- reply 说的是「先排一版」，没有声称已经生成。

## 示例 2：缺关键条件（intent = clarify）

动态上下文：

```json
{"当前表单":{"city":"","days":3},"当前北京时间":"2026-11-06 19:30 星期五"}
```

用户：

> 帮我安排个三天的小众路线，别太网红

输出：

```json
{"reply":"小众路线可以排，先确认一下城市，我就能按三天走。","intent":"clarify","form_patch":{"days":3,"interests":"小众、别太网红"},"place_keywords":[],"question":"想去哪个城市？"}
```

要点：

- 没有目的地，intent 走 clarify，不硬进 plan。
- question 只问一个问题；reply 给背景，不重复问题。
- 用户说的「三天」写进 form_patch；「小众」「别太网红」按原话进 interests。
