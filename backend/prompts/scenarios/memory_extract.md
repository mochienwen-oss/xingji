# 场景：长期记忆提取（memory_extract）

## 这一轮做什么

从对话里挑出**以后还用得上**的用户信息，写成结构化记忆。宁缺勿滥：没把握就不写。

## 输入

多轮对话（user / assistant / tool），可选：已有记忆列表。

## 输出形状

```json
{"memories":[{"category":"preference","scope":"travel","key":"","value":"","evidence":"","confidence":0.9}]}
```

没有可提取的内容时输出 {"memories":[]}。

## 字段

- category：enum，preference / feedback / project / resource。
  - preference：稳定的旅行偏好或习惯（怕晒、不爱排队、喜欢老街区）。
  - feedback：对产品、回答方式的要求（别一次问太多、少给营销词）。
  - project：长期项目约束（只做中国大陆、只排 1–5 天）。
  - resource：可复用的个人资源或固定条件（常驻城市、同行老人小孩、常用交通方式）。
- scope：enum，travel / product / workflow。
- key：稳定短键，小写下划线英文，≤30 字符；同一含义始终用同一个 key（pace_preference、avoid_crowds）。
- value：≤60 字，陈述句，主语是用户，不写「用户说」。
- evidence：≤40 字，必须是**用户消息里的原文片段**，可截取，不得改写，不得取自助手发言。
- confidence：0.0–1.0。用户直述给 0.9，需要轻推断给 0.7，低于 0.6 不要输出。

## 提取规则

1. 三条同时满足才提取：用户明确说过、未来仍然有用、可被这段话验证。缺一条就不写。
2. 最多 5 条；按重要程度排序，重要的在前。
3. 不提取一次性行程细节（「这次去杭州 3 天」「明天几点出发」）。
4. 不提取助手的建议、猜测、总结；不把「用户可能喜欢……」写成记忆。
5. 不提取提问、寒暄、临时情绪、表单里已经有的当前值。
6. 不提取敏感信息：密码、邮箱、手机号、身份证或护照号、银行卡、支付信息、精确住址、健康信息。用户主动说了也不记。
7. 与已有记忆重复的不再输出；冲突时只输出用户最新明确表达，key 保持一致。
8. value 写行为或偏好，不写评价：「每天最多安排 4 个点」，不写「用户很佛系」。
9. 只输出 JSON，不解释为什么提取或不提取。

## 示例（单条）

```json
{"category":"preference","scope":"travel","key":"pace_preference","value":"不喜欢赶行程，每天最多三四个点","evidence":"别排太满，我走不动","confidence":0.9}
```

## 自检

- 每条都能指回一句用户原话？evidence 是否逐字来自用户？
- 有没有一次性信息、助手猜测或敏感信息？
- key 是否稳定、可复用？value 是否超过 60 字？
- 条数 ≤5；JSON 能直接解析。
